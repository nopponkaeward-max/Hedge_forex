# การวิเคราะห์ความเสี่ยงพอร์ตแตก — Hedge Equation EA

> จัดทำหลังรอบตรวจบัค (commit ที่แก้ 11 ประเด็น) — **ตัวเลขความน่าจะเป็นในเอกสารนี้เป็นการประเมิน
> เชิงโครงสร้างก่อนมี backtest** ค่าจริงต้องวัดจาก backtest real-tick ≥ 2 ปี + Monte Carlo ตาม DESIGN §15
> ห้ามใช้ตัวเลขนี้ตัดสินใจลงเงินจริงโดยไม่ทดสอบเอง

## 1. นิยาม "พอร์ตแตก" — ระบบนี้มี 3 ระดับ ไม่ใช่ระดับเดียว

| ระดับ | ความหมาย | เกิดเมื่อ |
|-------|----------|-----------|
| A. Stop out จริง | โบรกบังคับปิด, Equity → 0 | Equity ≤ 0 หรือ ML% ≤ เกณฑ์โบรก แม้ขณะ Fully Hedge (MT5 stop out เมื่อ equity ≤ 0 ได้ — หนังสือเตือนเอง) |
| B. ติดล็อคขาดทุนหนัก | Zero Hedge ล็อคที่ DD 30%+ เงินไม่หาย แต่แช่แข็ง ถอนไม่ได้ กิน swap สองขา | การ์ด DD/ML ทำงาน "สำเร็จ" ในสถานการณ์เลวร้าย — นี่คือ outcome ที่ระบบออกแบบให้เกิดแทนการแตก |
| C. แตกโดยพฤติกรรม | ผู้ใช้ทนสถานะ B ไม่ไหว ตัดขาดทุนเองที่ก้นเหว หรือเติมเงินแล้วโดนซ้ำ | จิตวิทยา — ความเสี่ยงที่ใหญ่ที่สุดจริงของระบบตระกูล hedge-hold |

ประเด็นเชิงโครงสร้างที่ต้องเข้าใจก่อน: ระบบนี้**ไม่ตัดขาดทุน** มันแปลงการขาดทุนเป็น "สถานะล็อค"
ดังนั้นความน่าจะเป็นของ (A) ต่ำโดยดีไซน์ แต่แลกด้วยความน่าจะเป็นของ (B) ที่สูงกว่าระบบตัดขาดทุนมาก
— โปรไฟล์แบบ short volatility: กำไรเล็กสม่ำเสมอ, หางขาดทุนใหญ่และยาว

## 2. โซ่การป้องกันที่มีในโค้ด (ลำดับก่อนถึงจุดแตก)

```
NetLotMax (ML target 3000%) → DD 20% งดเพิ่มไม้ → DD 30% / ML 500% / S&R break
→ Zero Hedge ล็อค (net=0, margin≈0, P/L ฟรีซ) → [ค้างจนเทรนด์ชัด + DD < 20% จึงคลาย]
→ Stop out ได้ก็ต่อเมื่อ equity ไหลถึง 0 ระหว่างล็อค (swap + spread ถ่าง) หรือการล็อคล้มเหลว
```

จุดตายของโซ่ (single points of failure):
1. **คำสั่ง Zero Hedge เปิดไม่สำเร็จ** ขณะราคาวิ่งแรง (requote/off-quotes ช่วงข่าว) — โค้ด retry ทุก tick + ข้ามการ์ด spread/news แล้ว แต่โบรกปฏิเสธซ้ำได้ในตลาดสุดขั้ว
2. **Gap ข้าม DD threshold** — ราคากระโดด (เปิดตลาดจันทร์, ข่าวใหญ่) จาก DD 25% → 55% ใน tick เดียว การล็อคเกิด "ที่ราคาหลัง gap" ขาดทุนที่ฟรีซจึงใหญ่กว่า 30% ที่ตั้งไว้มาก
3. **โบรกคิด margin ตอน hedge** (`SYMBOL_MARGIN_HEDGED ≠ 0`) — สมมติฐาน margin≈0 พัง สถานะล็อคยังกิน margin และ stop out ได้ (EA ตรวจและเตือนตอน OnInit แล้ว — ห้ามใช้กับโบรกแบบนี้)
4. **Leverage จริงต่ำกว่า 1:2000 มาก** (เช่นโบรกกำกับ 1:30–1:100) — margin ต่อ lot สูง 20–60 เท่า ML% ทั้งระบบต่ำกว่าที่สมการคาด margin call มาก่อนการ์ดจะช่วย (EA เตือนตอน OnInit)

## 3. สถานการณ์เสี่ยงหลัก + การประเมิน

| # | สถานการณ์ | ผลลัพธ์ที่คาด | โอกาสเกิด/ปี (ประเมิน, XAUUSD default) |
|---|-----------|----------------|------------------------------------------|
| S1 | Sideway กว้างระดับสัปดาห์ → flip ซ้ำ → cover lot โตสะสม → ชน layer cap | สถานะ B (ล็อคที่ DD 20–35%) | **สูง (หลายสิบ %)** — sideway กว้างคือธรรมชาติของทอง ระบบนี้แพ้ทาง sideway โดยดีไซน์ (หนังสือยอมรับเองในบทที่ 6) |
| S2 | Weekend/news gap ข้าม DD threshold | สถานะ B แต่ล็อคที่ DD ลึกกว่า 30% มาก (40–60%) | ปานกลาง — ทองมี gap >1% หลายครั้ง/ปี; ลดได้ด้วยงดถือข้ามเสาร์อาทิตย์ (มี input `InpCloseFriday` แนวคิดใน DESIGN แต่ยังไม่บังคับปิดไม้) |
| S3 | Zero Hedge fail ช่วง flash move + ราคาวิ่งต่อ 5–10 นาที | DD ทะลุลึกก่อนล็อคติด → B ลึก หรือ A ถ้าทุนเล็กมาก | ต่ำ–ปานกลาง (ขึ้นกับโบรก); ทุน 1,000 USD + baseLot 0.01 มี buffer เยอะ |
| S4 | ติดล็อคนาน 3–6 เดือน → swap สองขากัด equity | equity ไหลช้า ๆ; ทองมี swap ติดลบทั้งสองฝั่งที่หลายโบรก ~1–3%/เดือนของ notional ที่ถือ | สะสมแน่นอนถ้าเกิด B นาน — นี่คือเส้นทางหลักจาก B → A ในระยะยาว |
| S5 | Config ผิด: baseLot ใหญ่เกินทุน / leverage ต่ำ / โบรก margin-hedge ≠ 0 | A ได้โดยตรง | ขึ้นกับผู้ใช้ทั้งหมด — EA validate + เตือนแล้ว แต่ไม่ block ทุกกรณี |
| S6 | บั๊กที่ยังไม่พบ (โค้ดยังไม่เคย compile/backtest) | พฤติกรรมนอกแบบ | **ยังสูงจนกว่าจะผ่าน backtest** — รอบตรวจนี้พบและแก้ 11 จุด รวม 4 จุดบนเส้นทางเงินหลัก แปลว่าก่อนตรวจ โอกาสพังจากบั๊กสูงมาก และไม่ควรถือว่าเป็นศูนย์หลังแก้ |

## 4. สรุปการประเมิน (ก่อน backtest — ใช้เป็นสมมติฐานให้ backtest หักล้าง)

เงื่อนไข: default ทั้งหมด, ทุน ≥ 1,000 USD, baseLot 0.01, โบรก margin-hedge = 0, leverage ≥ 1:500, XAUUSD

- **Stop out (A) ภายใน 1 ปี: ต่ำ — ราว <5–10%** เพราะโครงสร้างล็อคก่อนแตกและ lot ฐานเล็กเทียบทุน
  ตัวขับหลักของ A คือ S5 (config ผิด) และ S4 (ล็อคนานแล้ว swap กัด) ไม่ใช่การเคลื่อนของราคาโดยตรง
- **ติดล็อคขาดทุน ≥ 20–30% (B) ภายใน 1 ปี: ปานกลาง–สูง — ราว 30–60%** โดยเฉพาะถ้าตลาดมี
  sideway กว้างหรือ gap ใหญ่ นี่คือ "ราคาที่จ่าย" ของการไม่มี stop loss
- **เมื่อเกิด B แล้ว การกู้คืนไม่รับประกัน**: การคลายล็อคต้องการเทรนด์ชัด + DD < 20% ซึ่งอาจไม่มาเป็นเดือน
  ระหว่างนั้น swap เดินทางเดียว → ยิ่งนานยิ่งใกล้ A
- ระบบเหมาะกับ**ทุนที่พร้อมแช่แข็งได้ 30%+ เป็นเดือน** เท่านั้น ไม่เหมาะกับทุนที่ต้องใช้หรือทุนก้อนสุดท้าย

## 5. สิ่งที่ช่วยลดความเสี่ยงได้จริง (เรียงตามผลกระทบ)

1. **Backtest + demo ก่อนเสมอ** — วัด: จำนวนครั้งเข้า LOCKED, DD ลึกสุด ณ จุดล็อค, เวลาเฉลี่ยใน LOCKED, swap รวม, ML% ต่ำสุด (เกณฑ์ผ่านใน DESIGN §15)
2. **อย่าถือข้ามสุดสัปดาห์ช่วงข่าวใหญ่** (ลด S2) — เฟส 5 ควร implement บังคับ Zero Hedge เย็นวันศุกร์เป็น option
3. ใช้ **โบรก margin-hedge = 0 + leverage สูง** เท่านั้น (ตัด S5 ครึ่งหนึ่ง) — EA ตรวจให้แล้ว อ่านคำเตือนตอน OnInit
4. ตั้ง `InpHardCutPct` (เช่น 45–50%) เป็น **เพดานสุดท้าย** ใต้สถานะล็อค — นอกตำราแต่ตัดหาง S4 ทิ้ง แลกกับการ realize loss
5. ทุนต่อ instance ≥ 100,000 เท่าของ pip value ที่ baseLot (ทอง 0.01 lot ≈ ทุน ≥ 1,000–2,000 USD)
6. เริ่มที่ `InpMaxLayers = 1` — เข้มกว่าหนังสือหนึ่งขั้น ลดการสะสม lot ใน sideway
